Squarespace implementation handoff

Decision

Retain Squarespace 7.1, the existing domain, Shelterluv, animal records, applications and donation services. These browser concepts are a specification and review tool, not an installable theme ZIP. Translate the selected direction into the existing Squarespace editor.

Three design systems

  • 01 Clear & Kind: background #f5faf9, text #173d40, primary #176d70, soft surface #e2eeeb; clean sans-serif typography, 16px cards, pill buttons, right-side rectangular hero photo. Closest to the existing teal brand.
  • 02 A Little Home: background #fbf7ef, text #42362d, primary #954727, soft surface #eee5d7; serif headings, restrained square-ish buttons, left-side arched photo, a more personal/editorial feel.
  • 03 Northwest Companion: background #f6f6ed, text #1e3d31, primary #355b3b, hero action #e2e6ac; forest-green hero, serif headlines, minimal corner rounding, quieter editorial composition.

Fonts shown in the previews use system Arial and Georgia rather than adding hosted dependencies. Confirm equivalent choices in the rescue's Site Styles and available font library. The typographic heart/wordmark is an exploratory placeholder, not a recommendation to discard the existing logo. Obtain the rescue's original approved logo file before implementation.

Editor mapping

Header: existing Squarespace header controls and navigation. Keep the logo and existing URL destinations; prioritize Meet Our Dogs and make Donate/Support consistent. Prototype menus demonstrate information hierarchy, not the final native header code.

Homepage hero: a Fluid Engine section with native text, image and two button blocks. Image shape/mask can approximate the arch; if the current editor does not offer the needed shape, use a small scoped CSS rule, not a second page-building system. Create a separate deliberate mobile arrangement.

Adoption stages: three native content columns on home; a fuller ordered sequence on the adoption page. Accordion block for FAQs. Copy is based on the published process but still needs rescue approval.

Dog directory: retain the existing Shelterluv code block, GID and wrapper ID. Remove unnecessary surrounding page height. Give the frame an accessible title and full available width. Use the supported vendor resize script rather than guessing a fixed document height. Confirm settings in Shelterluv before changing column/filter configuration. The one-column setting may be intentional; verify desktop needs first.

Featured dog story: optional manual Squarespace editorial page using native image/text blocks. A clear date/current-listing link prevents a stale story from pretending to be an available-dogs database. If the team cannot maintain these, omit this optional feature and use a general rescue story instead.

Contact: retain the current Squarespace form and its configured storage/routing. Add visible email and adoption-routing help. The prototypes omit form submission deliberately; this is not a recommendation to remove the real form. Verify newsletter consent defaults and accessible labels before publishing.

Foster/volunteer/support: keep their existing pages and destinations. Apply the selected type scale, spacing, imagery and shorter action-first summaries. The preview's combined ways-to-help screen is a navigation aid, not a mandate to delete existing detail pages.

Footer: canonical contact email, staff-confirmed address purpose, policy pages with approved content, consistent support links, corrected credit/copyright wording.

Keep / change / do not promise

Keep animal entry, status changes, photos and applications in Shelterluv. Keep site editing in Squarespace. Keep existing donation checkout until separately reviewed.

Change native layout, color, typography, image treatment, surrounding directory space, information hierarchy, labels, policy content and broken internal links.

Do not promise a fully branded Shelterluv gallery, custom filters, native Squarespace dog share metadata or automatic featured-story synchronization through site CSS. The frame is cross-origin. A custom API integration would add credential management, a separate service, data freshness rules and support burden; excluded from this design-only scope.

Safe implementation sequence

  1. Rescue chooses a concept and approves its logo, photo use and content.
  2. Request an appropriate collaborator invitation via the platforms' normal account flow, not shared passwords.
  3. Record current Site Styles, custom CSS and code injections, navigation, embed snippet, page URLs and form/storage settings. Use the owner's existing backup/export practice; save screenshots and copies of custom code. Squarespace duplication is not a full backup of every integration.
  4. Duplicate relevant pages and hide drafts from navigation/search; password-protect a review surface where supported. “Not Linked” and noindex alone are not privacy controls. Avoid changing global Site Styles on the live site while drafting; use a controlled preview or draft-scoped styles until the final cutover.
  5. Build the selected native page layout. Keep the original Shelterluv wrapper ID during final replacement so existing deep links remain compatible. Do not include two identical wrapper IDs on one page.
  6. Validate links and mobile breakpoints; check the exact iPhone/Safari screenshot issue; test frame loading, gallery, filters, name search and back/deep-link behavior.
  7. Coordinate clearly identified test applications, contact messages and donations with the rescue. Verify inbox delivery, acknowledgments and receipts. None were submitted for these prototypes.
  8. Obtain rescue approval of concrete final pages before any production cutover. Preserve live routes and explicit redirect mappings. Keep rollback copies and reverse style changes if needed.

Acceptance criteria

  • Dog directory, application/process, general contact and donate routes are easy to find on a phone.
  • No horizontal scrolling or distorted images at 320, 390, 768 and 1440 CSS pixels; actual iPhone Safari check required.
  • One meaningful main heading, logical headings, keyboard reachability, visible focus, usable touch targets and verified text contrast. Native accessibility issues addressed; overlay presence is not a pass.
  • Shelterluv retains current data, functional filters, accessible photo controls and existing dog links.
  • Contact and application confirmation/delivery verified with staff; payment receipt verified through an agreed test.
  • Privacy, terms and accessibility pages have accurate approved contents. No unsupported rescue statistics, medical promises or fee claims.
  • Known broken donation path fixed; stale URLs have intentional treatment; sitemap reviewed.
  • Staff can update normal content without editing application code. No new animal database, paid integration or migration required.

Estimate, not a quote

A style/layout refresh with approved copy could take roughly 3–6 implementation days plus staff review. Contact/policy clarification, Safari/vendor debugging and checkout testing can extend that. The actual subscription plan, editor state, integrations and approval turnaround have not been inspected administratively. Work should be scheduled after the rescue selects a direction, not before.

Prototype verification and review

Plain HTML, CSS and browser JavaScript; no framework/build system, no backend, no tracking added by the prototype. Three concepts × six page types × two viewport sizes were checked in Chromium. Initial 36 checks found no horizontal overflow, broken loaded images or JavaScript exceptions; navigation, photo changes and exit-dialog open/Escape close worked. The existing Shelterluv frame loaded in every directory variant.

Screenshot inspection identified a too-tall hero image caused by HTML dimension attributes; CSS height handling was corrected, then relevant visual checks were repeated. Test scripts and detailed evidence are retained locally, not published with private workspace information. Hosted smoke results are recorded separately after deployment. Actual iPhone/Safari, full screen-reader conformance, native Squarespace installation and real form/payment delivery remain unverified.

Five-axis review: URL parameters are allowlisted before rendering; only fixed trusted template content enters HTML; no submitted user data or credentials are handled; official handoffs are labeled; vendor code loads only on directory pages; all dog-source images are tracked in asset provenance. Preview code is intentionally separate from production. A manual featured story is explicitly labeled and not silently sold as an automatic API integration.

Sharing

The review hub offers all three concepts, audit and implementation plan. It adds no feedback collection; recipients can send their preferences to the person sharing it. The pages contain noindex metadata, but hosting is not private or password-protected. Shelterluv and the hosting provider may operate their own logging/services. Do not describe the preview as collecting no data at all.
